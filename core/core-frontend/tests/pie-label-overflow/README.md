# 圆形图长标签回归

适用 dev-v3 的 G2 v5 饼图、环形图、玫瑰图外侧标签；不改内侧标签和现有高密度采样规则。原有处理在完整显示模式下没有文本宽度或边界限制，长名称会超出画布。新处理优先两行、冲突回退省略；完整显示不隐藏标签，普通模式允许避让隐藏。移动文字时保持引导线的扇区端坐标不变。

## 本地运行

在 `core/core-frontend` 安装项目依赖后执行：

```sh
node node_modules/vite/bin/vite.js --config tests/pie-label-overflow/vite.config.ts
```

打开 http://127.0.0.1:7087/ 。默认 40 个中文长标签，可切换完整显示、数量、字号，左右对照原实现和修复实现。此页面直接导入生产布局函数，不依赖后端或修改业务数据。

## 自动化

需要 Python Playwright 和 Chromium，执行：

```sh
python3 tests/pie-label-overflow/check.py
```

可用 `PIE_TEST_URL` 指定其他服务地址。72 组组合覆盖数量 3/40/80、宽度 280/390/760、字号 12/32、普通/完整显示、饼图/玫瑰图。断言：

- 完整显示时标签数量等于输入数量，文字非空并带引导线。
- 文字边界在画布内；普通模式可见标签不重叠。
- 确实发生换行，原实现确实存在越界，避免测试空跑。
- 浏览器无运行时异常。截图输出 `/tmp/dataease-v3-pie-label-overflow.png`。

## 产品内验收用例

新建独立测试数据集，字段 `field` 为“上海人身险平台数据治理部门1”至“部门40”，`value` 为 5 至 44。新建测试仪表板，不修改业务仪表板。

1. 创建环形图，维度选择 field、指标选择 value，启用外侧标签和完整显示，40 个标签都应保留。
2. 将组件宽度调为 280/390/760px、字号调为 12/32px，确认文字不被画布裁剪，引导线仍连接原扇区。
3. 关闭完整显示，确认换行冲突后省略、必要时隐藏；内侧标签行为保持原样。
4. 点击图例筛选并恢复、重复缩放组件、保存后重新打开，检查标签不逐次偏移。
5. 改为玫瑰图重复上述操作；增加至 80 行检查完整显示不触发现有采样。

自动化验证的是实际 G2 渲染层，不代表完整 DataEase 应用构建、产品内保存重开或全部公共图例回归已通过。
