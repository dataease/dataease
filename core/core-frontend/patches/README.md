# 地图依赖补丁使用与维护

本目录用于修复 TAPD 缺陷 `1140899682001077770` 排查中确认的 L7 地图生命周期问题。补丁仅涉及地图依赖，不包含大屏通用组件或 UI 库修复。

## 1. 补丁是什么，为什么需要保留

`.patch` 是“原始依赖代码与修复后代码之间的差异”，不是完整依赖包，也不是测试文件。安装依赖后，`patch-package` 按差异修改本地 `node_modules`，让其他开发者和构建环境得到同样的修复。

仅手动修改 `node_modules` 会在重新安装时丢失；把补丁保存在项目中，可以重复应用并审查具体改动。补丁不会修改 npm 上发布的包，也不会在用户打开地图时动态执行；修复后的依赖代码随前端构建进入产物。

文件中的标记含义：

| 标记                     | 含义                                       |
| ------------------------ | ------------------------------------------ |
| `diff --git a/... b/...` | 本段修改的依赖文件                         |
| `---` / `+++`            | 修改前、修改后的文件路径                   |
| `@@ ... @@`              | 修改位置和上下文范围                       |
| 行首 `-` / `+`           | 删除、增加的代码                           |
| 行首空格                 | 用来定位修改位置的原有代码                 |
| `index ...`              | 差异文件的版本标识，不是需要填写的业务参数 |

文件名中的 `+` 用于编码依赖名称和版本，例如 `@antv+l7-core+2.23.1.patch` 对应 `@antv/l7-core@2.23.1`，不应随意改名。

## 2. 两个补丁的具体作用

| 文件                           | 修改位置                   | 修复行为                                                                                                                                              |
| ------------------------------ | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@antv+l7-core+2.23.1.patch`   | `ConfigService` 及类型声明 | 增加按场景 ID、图层 ID 删除配置缓存的方法，不清空其他地图的缓存                                                                                       |
| 同上                           | `SceneService` 及类型声明  | 保存并解绑像素比例媒体查询监听；卸载尺寸检测器；避免重复销毁；处理初始化期间的销毁请求；先发出 `destroy` 事件，再移除事件监听；销毁时删除当前场景配置 |
| 同上                           | `InteractionService`       | 解绑 `mousedown` 时使用与注册一致的捕获参数，并补齐 `touchmove` 解绑                                                                                  |
| `@antv+l7-layers+2.23.1.patch` | `BaseLayer`                | 图层销毁时删除对应的图层配置和属性配置缓存                                                                                                            |

两个补丁需要配套使用：图层补丁会调用核心补丁新增的 `removeLayerConfig()`。不能只保留图层补丁。

每个补丁同时覆盖 `es/` 和 `lib/`，分别对应 ESM 和 CommonJS 入口；核心补丁还同步修改 `.d.ts` 类型声明。这是文件看起来较长的原因，不是两套不同的修复。

### 与业务代码的分工

- `src/views/chart/components/js/panel/charts/map/tooltip-position.ts`：管理 Tooltip 定位监听和动画帧的解绑
- `src/views/chart/components/views/components/ChartComponentG2Plot.vue`：管理地图重建、定时器取消和实例销毁；地图与 G2 共用任务队列和版本号，切换时不复用其他渲染库的实例，异步返回的过期实例及时销毁
- 本目录补丁：让业务代码调用地图销毁方法后，L7 内部资源也得到清理

不能仅靠删除 Tooltip 的 WeakMap 条目替代 L7 内部清理。WeakMap 的值引用其键本身也不等于已经证明内存泄漏，需结合实际持有者判断。

## 3. 日常使用

以下命令均在 `core/core-frontend` 目录执行。

项目 `package.json` 已配置：

```json
{
  "scripts": {
    "postinstall": "patch-package --error-on-fail --error-on-warn"
  },
  "devDependencies": {
    "patch-package": "8.0.1"
  }
}
```

正常安装即可自动应用：

```sh
npm install
```

已安装依赖时，可以手动重新应用并检查退出状态：

```sh
npm run postinstall
```

日志应显示两个包的补丁应用成功，命令退出码为 `0`。重复应用已经生效的补丁应成功，不会重复添加代码。

开发及前端构建阶段需要安装开发依赖，并允许执行安装脚本。使用 `--ignore-scripts` 会跳过自动应用；仅安装生产依赖可能缺少 `patch-package`，不能据此认为补丁已经生效。

CI 或容器构建也必须在执行依赖安装前具备 `patches/` 目录。若缓存 `node_modules`，缓存失效条件应包含补丁文件的变化；跳过安装直接恢复缓存时，需显式执行 `npm run postinstall`。

应用补丁后，重启开发服务并刷新测试页面。Vite 可能仍使用旧的依赖预构建缓存，可执行：

```sh
npm run dev -- --force
```

这只用于开发依赖重新预构建，不代替发布环境重新构建前端产物。

## 4. 如何修改补丁内容

补丁中的修复逻辑由本项目维护者负责；`patch-package` 负责生成和应用差异，不会自动判断修复是否正确，也不会自动适配新版 L7。

维护同一版本时，建议由开发者手动执行以下步骤：

1. 确认依赖版本，以及当前两份补丁已成功应用
2. 在本地 `node_modules/@antv/l7-core` 或 `node_modules/@antv/l7-layers` 中修改必要代码，保持 ESM、CommonJS 和相关类型声明一致
3. 使用已安装的工具重新生成完整补丁；生成结果应包含原有修复和本次调整

```sh
npm ls @antv/l7 @antv/l7-core @antv/l7-layers @antv/l7plot
./node_modules/.bin/patch-package @antv/l7-core
./node_modules/.bin/patch-package @antv/l7-layers
```

4. 审查生成的差异，排除 source map、调试输出、测试内容和无关依赖修改
5. 在独立、干净的依赖安装环境中验证首次应用，再验证重复应用；不要只验证当前已经修改过的 `node_modules`
6. 按下一节验证地图行为，并同步更新本说明

上述生成命令提供给开发者手动使用，本文不代表代理获得 Git 写操作授权。生成过程可能使用临时 Git 工作区；不要把“生成补丁”和“将项目改动提交到 Git”混为一谈。

不建议直接编辑 `.patch` 中的行号、上下文和差异标记。若手工调整，必须重新验证从原始依赖应用补丁的结果。

## 5. 验证要求

每次修改或升级至少检查：

- 两张地图同时存在时，销毁其中一张不影响另一张的显示、交互和缓存
- 连续重绘、切换地图，Tooltip 定位仍正确，监听数量不按轮次增长
- 异步建图尚未结束就重绘或卸载，旧实例仍能清理，过期请求不覆盖新实例
- 地图与 G2 双向切换，覆盖防抖等待、建图等待和渲染等待阶段；确认 G2 增量刷新及 L7 同库实例复用仍然正常
- 卸载后，对应场景和图层缓存归零；旧容器可以被垃圾回收
- 经过预热、多轮操作和垃圾回收后，堆内存不出现随轮次持续累积的趋势
- 补丁首次应用、重复应用成功，不兼容内容应用失败

仅有 `npm run postinstall` 成功，不代表地图行为和内存验证通过。全页 DOM 数或内存还会受到其他组件影响，需要区分地图泄漏与其他已知问题。

## 6. 升级依赖、应用失败与移除补丁

当前补丁针对 `@antv/l7-core@2.23.1` 和 `@antv/l7-layers@2.23.1`。项目同时使用 L7 和 L7Plot；检查版本时应包含它们的实际依赖树，避免遗漏嵌套的另一份 L7。

升级时不要直接把补丁文件名改成新版本：

1. 阅读新版本的对应实现，确认哪些问题已被上游修复
2. 在隔离环境中对新版本复现、验证；仅为仍然存在的问题重新生成补丁
3. 配套替换核心和图层补丁，核对新增方法及类型声明是否仍匹配
4. 完成上述地图验证后，再交付依赖版本和补丁的变更

应用失败时先检查实际版本、目标文件内容、补丁目录是否完整，以及缓存中是否残留旧依赖。不要通过删除 `--error-on-fail`、`--error-on-warn` 或忽略错误来继续构建：这可能产生未包含修复的产物。

当上游版本已覆盖所需修复且回归通过，可以删除对应补丁；若核心新增方法仍被图层补丁调用，必须一起调整。删除补丁文件不会自动撤销已经写入本地 `node_modules` 的修改，需要在干净安装环境中验证移除后的行为。

只有项目不再需要任何补丁时，才移除 `postinstall` 中的调用和 `patch-package` 开发依赖。业务层生命周期清理是否保留，需要单独依据代码判断。

## 7. 建议交付内容

一起交付两个 `.patch` 文件、本说明、`package.json` 中的接入配置及对应地图业务修复。不要提交 `node_modules`、测试产物或临时补丁生成目录；按项目既有规则处理依赖锁文件，不为补丁重建无关依赖。
