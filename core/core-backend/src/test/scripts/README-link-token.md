# Link Token 认证回归

范围：V3 核心、License SDK 和 XPack 的 Link Token、普通登录 Header/Cookie 认证。

## 运行

依赖已经安装，三个工作区已有可用的编译产物。先在同级 `dataease-license-sdk` 执行：

```sh
mvn -o -q -DskipTests compile
```

随后在 DataEase 根目录执行：

```sh
python3 core/core-backend/src/test/scripts/run-link-token-regression.py
```

脚本把受影响的源码编译到临时目录，分别执行核心、网关和登录验证器回归。仅使用内存中的用户、分享记录、缓存及测试密钥，不启动应用、不连接数据库、不调用网关、不读取部署密钥。临时目录在退出时清理。

它依赖当前 SDK/module classes 和本机 Maven 缓存，属于局部源码回归，不代替标准构建或真实部署集成测试，也不代表默认跳过测试的 `mvn test` 已执行。

## 升级行为

- License SDK、核心和 XPack 必须配套构建更新。未安装验证实现时认证失败，不退回只解码。
- 旧 Link Token 失效。分享 URL 保留；重新打开链接并按原流程输入密码/校验 ticket 后获得新令牌。
- 新分享令牌最长八小时，且不超过分享本身的有效期。永久分享 URL 不变，令牌到期后需重新打开链接换取。
- 分享令牌使用服务端秘密签名，绑定分享 ID、创建者、资源、组织和当前分享设置；修改密码、URL、到期时间、ticket 要求或访客权限后，原状态签发的令牌不再通过验证。
- 各实例必须使用一致、持久化的分享秘密。读取或持久化失败时启动失败，避免使用无法恢复的临时秘密。
- 普通登录保留现有合法签发规则；共享 Header/Cookie 验证入口，不再依赖 License 状态跳过校验。
- 分享允许的接口由既有 `DeLinkPermit` 与有限的辅助接口确定。画布、图表、查询字段和图片须在分享范围内；编辑快照及编辑恢复被拒绝。

生产代码改动集中在认证、分享签发和分享权限组件，没有修改图表、数据集或可视化业务服务、前端与数据库结构。V2 未改动。

## 实机验证与已知限制

已在本地前后端验证普通登录、工作台、分享页面和图表取数；伪造/篡改令牌、身份类型混用、跨资源、编辑态/快照读取及范围外查询字段均被拒绝。测试分享未启用导出，验证了拒绝行为，未覆盖允许导出的完整流程。

仍保留认证 Cookie。本次已知兼容性问题：静态资源认证优先采用分享 Cookie，浏览器同时保留登录和分享 Cookie 时，分享范围外的静态路径可能被 401 拒绝，即使登录凭证有效。此问题暂不处理，不应据此宣称所有场景均已修复。

实际网关转发、嵌入、移动端、跨用户/组织、带密码分享、正常复杂筛选、子画布及图片完整视觉链路尚未完成实机回归。
