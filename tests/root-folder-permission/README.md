# 资源目标目录鉴权回归（TAPD 1079845）

正式创建和移动资源时，通过 `InteractiveAuthApi.checkWriteDestination()` 检查目标目录管理权。根目录不是普通资源 ID 的免检情况。核心的兼容入口负责身份检查及实际单用户社区替补模式；企业授权判断由权限提供方统一执行。旧权限提供方继承的新契约默认拒绝，不能回退到原先跳过 ID 0 的 `checkAuth()`。

## 核心接入范围

- 数据源文件夹、新建数据源、移动。已有数据源更新继续使用存储中的父目录。
- 数据集文件夹、叶子创建和移动；保存接口仅在实际新建或显式改变父目录时检查，原目录更新不增加父目录管理权要求。
- 仪表板、大屏正式保存和移动；应用导入在写入前同时检查画布及数据集目标目录。
- 仪表板更新仅在父目录变化时检查，保留原目录更新、复制临时草稿及模板解压路径。
- 带素材包的正式保存，在恢复素材文件及元数据前也执行目标预检。

没有改动前端、普通资源 ID 0 鉴权规则、数据库结构、权限继承及缓存失效路径。无权请求必须在业务保存、应用导入或素材恢复前拒绝。

## 执行隔离回归

使用 Java 21 和已安装依赖；不启动产品或连接业务数据库：

```sh
mvn -o -q -f core/core-backend/pom.xml dependency:build-classpath -Dmdep.outputFile=/tmp/tapd-1079845-classpath
python3 tests/root-folder-permission/run.py --classpath-file /tmp/tapd-1079845-classpath
```

隔离工作区可以通过 `--compiled-root` 指向具有匹配基础编译产物的工作区。脚本重新编译本次核心及 SDK 源码到临时目录，优先使用新类，不以旧 Server 二进制替代本次修改。依赖类路径不得包含 XPack 实现模块，以单独验证社区上下文。

覆盖新契约委托、服务缺失与异常拒绝、旧提供方默认拒绝、匿名/分享拒绝、社区替补与代理限制、叶子资源创建拒绝、原目录更新兼容、父目录变化检查、应用数据集目标预检及素材恢复前拒绝。权限提供方和持久化边界使用模拟数据，不把“未调用保存层”表述为真实数据库无落库验证。

## 兼容性与交付

需要同时交付包含新契约的 api-permissions、核心及匹配的权限实现；扩展创建/移动入口也依赖该契约。先准备匹配的 SDK 和权限提供方，再升级调用方。新核心配旧权限实现时，创建/移动会安全拒绝，不能把这种组合宣称为功能兼容。实际单用户社区版无需引入 XPack 实现模块。

未修改历史记录，不自动补授权、改组织或清理缺陷复现资源。目录不可见需要分别核实权限登记、组织归属、许可与缓存，不能仅凭树中缺失判断没有登记。
